# แพตช์ทดลองเมนูภาษาไทย

ติดตั้งเฉพาะ 5 ปุ่มหน้าเมนูหลัก: เล่นคนเดียว, เล่นหลายคน, ข้อมูลผู้เล่น, ตั้งค่าเกมนี้, ออกจากเกม

## สถานะการทดสอบ

สร้างและติดตั้งไฟล์ทดลองแล้ว ตรวจอ่าน PFF ที่สร้างกลับและเทียบข้อมูลสมาชิกครบ 3,975 รายการผ่าน เปลี่ยนเฉพาะสมาชิก `menutxt.bin` และ `Impact50.fnt` ภายใน `localres.pff` สำหรับเมนู ไม่แก้ executable ต้นฉบับที่โฟลเดอร์หลัก การแก้ IME เพิ่มเติมอยู่ในสำเนาทดลองใต้ `RunMenuTest` เท่านั้น

**ยังไม่ยืนยันภาพเมนูไทยในเกมจริง** แก้การตรวจ DirectX ที่ขาด `dpnhpast.dll` แล้ว และสำเนาทดลองที่ปิด IME ตอนเริ่มโปรเซสขึ้นหน้าต่าง Select Video Card ได้ แต่ภายใต้เซสชันทดสอบนี้การเรียก HAL GetDeviceCaps ยังคืน `0x8876086A` (D3DERR_NOTAVAILABLE) จึงต้องลองเปิดตัวทดสอบจาก Windows Explorer โดยตรงเพื่อแยกข้อจำกัดของเซสชันออกจากปัญหาฝั่งเครื่อง ไม่ถือว่าข้อผิดพลาดนี้พิสูจน์ว่า GTX 1050 Ti ไม่รองรับกราฟิกเหล่านี้

เปิดทดสอบด้วย `Run-ThaiMenu-Test.cmd` ในโฟลเดอร์ ThaiPatch โดยดับเบิลคลิกจาก Explorer ตัวเปิดใช้ `RunMenuTest/dfbhd.exe` ที่มีแพตช์ IME และตั้งค่าหน้าต่าง 800×600 แยกไว้ ไฟล์ root `dfbhd.exe` ยังมี SHA-256 เดิม และคืนค่า root `df.cfg` กับ `dfv.cfg` ตามสำรองแล้ว

ภาพ `evidence/thai-menu-atlas-preview.png` เป็นภาพจาก atlas ฟอนต์ที่สร้าง **ไม่ใช่ screenshot ในเกม** ตรวจด้วยสายตาแล้วคำว่า “นี้” มีสระอีและไม้โทซ้อนชั้น และคำว่า “ตั้งค่า” มีไม้หันอากาศกับไม้โทไม่หาย ภาพจริงหลัง engine วาด การย่อขยาย การตัดขอบ และพื้นที่คลิกยังรอทดสอบ

## วิธีจัดสระและวรรณยุกต์

ใช้ Tahoma Bold ของ Windows ให้ GDI `ExtTextOutW` จัดรูปข้อความทั้งป้ายก่อน แล้วเก็บภาพข้อความที่จัดแล้วใน atlas ใหม่ของ FNT0 ป้ายทั้ง 5 ใช้รหัสทดลอง 0xA1–0xA5 โดยคง glyph ASCII เดิมไว้

วิธีนี้ทำให้สระและวรรณยุกต์อยู่ตำแหน่งเดียวกับข้อความที่จัดรูปไว้ ไม่ต้องให้ engine เก่าจัด combining marks ทีละตัว เป็นวิธีทดลองสำหรับป้ายเมนูคงที่ **ไม่ได้เพิ่มการรองรับ Unicode ภาษาไทยทั่วไป** และยังไม่ได้รองรับการพิมพ์ชื่อไทยหรือข้อความแปรผัน ปุ่มทดลองใช้เมาส์; เอา `{hot}` ออกจากข้อความทั้ง 5 ปุ่ม จึงยังไม่รักษาปุ่มลัดตัวอักษรเดิม

## สำรองและถอน

ปิดเกมก่อนเสมอ แล้วเปิด `Restore-Menu.cmd` เพื่อคืน `localres.pff` เดิม สคริปต์ตรวจ SHA-256 ของสำรองและไฟล์ที่ติดตั้งก่อนคืนค่า ไฟล์ต้นฉบับอยู่ที่ `backup-menu-test/localres.pff` อย่าลบก่อนถอน

ติดตั้งซ้ำด้วย `Install-Menu.cmd` สคริปต์ใช้ Python/Pillow ที่มีในเครื่องนี้ ข้อมูลข้อความต้นฉบับและ offsets ไม่ได้ถูกเขียนทับนอกช่วงข้อความเป้าหมาย สำเนาข้อความและ hash อยู่ใน `build-menu-test/manifest.json`

## ปัญหาการเปิดเกมที่พบระหว่างทดสอบ

1. เริ่มต้นเกมออกด้วย `0xC0000022` ตรวจพบว่า `C:/Windows/SysWOW64/dplayx.dll` เป็น stub 10,240 ไบต์และไม่มี export ที่เกมต้องการ จึงถอดข้อมูล DCS/LZMS ของ DirectPlay DLL ที่มีอยู่แล้วใน Windows component store มาเป็น `dplayx.dll` เฉพาะโฟลเดอร์เกม ขนาด 226,816 ไบต์ ไม่ได้ติดตั้ง Windows feature หรือแก้ไฟล์ระบบ
2. DLL ที่เพิ่มมี SHA-256 `fb780f6029f0bd474a4a2d49f9d9d9f2653ed884c5a9b7aa2a564919447941c8` ไม่มีไฟล์ชื่อนี้ในโฟลเดอร์เกมก่อนทดสอบ การถอนเมนูจะคง DLL ช่วยเปิดเกมไว้
3. ผู้ใช้ติดตั้งส่วนเสริมและเพิ่ม d3d8to9 `d3d8.dll` จากต้นทาง https://github.com/crosire/d3d8to9/releases/tag/v1.16.0 ยืนยันจาก module snapshot ว่าเกมโหลด DLL ในโฟลเดอร์เกมจริง ไฟล์มี SHA-256 `122928cfe225c25d30decf7184a5d37e490cecf3b58256ba3206c7e1853f8ab8`
4. REA ถอด `FUN_005afcd0` พบว่าเกมรายงาน DirectX 8.1 not detected เมื่อ `LoadLibraryA("dpnhpast.dll")` ล้มเหลว ก่อนเรียก Direct3DCreate8 จึงเติม DLL จาก Windows component store เฉพาะโฟลเดอร์เกม ขนาด 10,240 ไบต์ SHA-256 `6b06c8de7b4b7111e2432c47b34125bd20d9f92cdbe20917d0ca1c661fbe8106` แล้ว log เปลี่ยนเป็น DirectX 8.1 detected หลักฐาน `ev_6f471e2aecb6698fd76b62f09c626f9050e72cd7cdb49c6a8f0a885cde0c49a8` ใน `evidence/rea-directx-startup-bundle.json`
5. ภาพ crash อ่าน memory `0x003C000E` ที่ instruction `0x75F0E5F8` ตรงกับ module MSCTF.dll RVA `0x2e5f8` จาก snapshot ของโปรเซสทดสอบ ได้ทดลองสำเนาที่เพิ่ม startup section เรียก ImmDisableIME ก่อน entry เดิม แล้วขึ้น Select Video Card ได้ ภาพอยู่ใน `evidence/select-video-card.png` และรายละเอียด byte/hash อยู่ใน `evidence/ime-test-manifest.json` วิธีนี้ปิด IME เฉพาะโปรเซสทดสอบ ไม่ได้เพิ่มการพิมพ์ไทยในเกม API อ้างอิง: https://learn.microsoft.com/en-us/windows/win32/api/imm/nf-imm-immdisableime
6. หน้าต่างเลือกการ์ดภายใต้เซสชันยังรายงาน hardware features ใช้ไม่ได้ สอดคล้องกับ native API probe ที่คืน D3DERR_NOTAVAILABLE จึงยังไม่ติดตั้งสำเนา EXE นี้ทับ root และยังต้องทดสอบการเปิดผ่าน Explorer ตามขั้นตอนด้านบน

DLL ของ Microsoft ที่ใช้เป็นสำเนาจาก Windows เครื่องนี้สำหรับทดสอบในเครื่องนี้ ไม่รวมไว้ในแพ็กแจก การถอนแบบคืนสภาพทั้งหมดให้ปิดโปรเซสทดสอบ คืน localres ผ่าน Restore-Menu.cmd แล้วแยกเก็บ DLL ที่เพิ่ม (`dplayx.dll`, `dpnhpast.dll`, และ `d3d8.dll` ที่ผู้ใช้เพิ่ม) ตาม hash ก่อนย้ายออก เก็บโฟลเดอร์สำรองไว้ตลอด ไม่จำเป็นต้องแก้ registry Compatibility ของ Windows
